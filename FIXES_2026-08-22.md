# NOVAWORKS — Interface & Workflow Fixes (2026-08-22)

This build includes:

- Fixed Property Types runtime crash caused by old/new data-shape mismatch.
- Property Types now support: key, singular label, plural label, description, image, enabled, show on homepage.
- Homepage renders only property types explicitly marked for homepage display.
- Add Property loads enabled property types dynamically.
- User Edit modal redesigned horizontally with a compact photo area.
- Password strength UI added to public signup, Add Staff, and forced password-change page.
- Password fields remain red while weak and turn green when all password requirements pass.
- Homepage newsletter subscription no longer requires an OTP. Subscription is activated immediately, the form clears, a success notification animates in, and a welcome email is sent.
- NOVA AI now uses OpenAI Responses API with live NOVAWORKS context, clearer provider errors, and a model fallback for invalid-model errors.
- System Health now performs a real OpenAI generation test instead of only checking whether the API key exists.
- R2 upload signing now honors R2_ENDPOINT from .env.

## Password reset flow

The existing flow is retained and verified in source:
1. User enters account email and reset reason.
2. A pending request is created without exposing whether an account exists.
3. IT sees the request in Password Reset Queue.
4. IT approves or denies it.
5. On approval a temporary password is generated and emailed to the user's account.
6. The account is marked must_change_password=1.
7. After login with the temporary password, the welcome route forces the user to Create New Password.
8. The new password is validated as 9+ characters with uppercase, lowercase, number and symbol.
